# 19: 只在明确授权的环境发布并验证产物

**执行角色：** backend

**What to build:** 对承诺上线的计划，在指定环境发布已验证产物并核实结果；负责人可区分已合入、已发布、上线已验证。

**Blocked by:** [18 在集成版本全量验证并交付产物](18-integrated-artifact.md)

**Status:** ready-for-agent

**GitHub 实施票：** [#20](https://github.com/linxiovo/deepseek-harness-dev-hub/issues/20)

**对应规格：** [S15](../spec.md#s15)、[S21](../spec.md#s21)

**依赖理由：** 18 交付可信产物引用、集成证据和仍待发布验证的计划状态。没有这份产物不应触发环境变更。

## 验收条件

- [ ] 覆盖无生产授权但有凭据、只有修复授权或调额、目标/范围不符三例：均没有生产写入。若承诺发布但缺凭据，只给受控入口，条件未验证不执行。
- [ ] 在受控目标环境走完整授权路径，实际部署的版本/产物与集成回归匹配，环境验证成功后才正式交付；通知分别给出产物、实际发布和验证结果。
- [ ] 发布失败显示「已合入，未上线」；已部署但环境验证失败显示已发生的动作及未验证状态。两者均不把含上线承诺的计划标为完成，不重新合入或谎报已回滚。
