# 06: 从规格自动登记可派工的 Plan DAG

**执行角色：** backend

**What to build:** 规格一产出，中枢就委派无人值守版 to-tickets，按「后端与接口契约先行、前端分离接续」规则拆解并登记可查询的 Plan DAG；负责人不需要再手工触发拆票或排依赖。

**Blocked by:** [02 在 Harness 交棒并自动取得规格](02-harness-handoff-spec.md)

**Status:** ready-for-agent

**GitHub 实施票：** [#7](https://github.com/linxiovo/deepseek-harness-dev-hub/issues/7)

**对应规格：** [S03](../spec.md#s03)、[S33](../spec.md#s33)

**依赖理由：** 需要 02 交付的已授权规格句柄及其完成事件来自动接续。可独立演示到「计划已登记，等待可用执行槽」，本票不启动 Worker。

## 验收条件

- [ ] 从已确认规格自动生成拆票计划：凡同时涉及后端与前端的功能，必须拆分为「后端 + 接口契约文档票（标注 `backend`）」与显式 `Blocked by` 它的「前端页面票（标注 `frontend`）」，不在同一张票内自动切换前后端模型；各自按独立可演示的功能切片组织、带稳定标识与规格验收引用，不找用户确认粒度。
- [ ] 登记「后端先交接口文档、前端后置依赖」「两项独立加一项需两者」与「单点维护」计划；查询分别得到正确的 `backend`/`frontend` 角色标签、前置阻塞边与分端统计，一次交棒能对应多票。
- [ ] 提交含重复节点、悬空引用、自环或多节点环、缺执行标签，以及把前后端需求混成单票且未列接口文档要求的非法计划时，程序拒绝并给出可定位错误，旧计划不被部分替换，没有任何节点被派发。
- [ ] 对根话题追加背景只更新计划上下文；定向给一张票的指令只交给相应节点。消息可读性与 Thread 订阅都不充当授权或依赖边。
