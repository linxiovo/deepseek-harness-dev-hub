# 08: 在 Worker Session 内按影响完成红绿验证

**执行角色：** backend

**What to build:** 在某张票的公开行为上运行 implement / tdd 与 test-scope，让接手者能从候选结果看出测了什么、为什么只测这些或为何必须全测。

**Blocked by:** [03 为每张票交付可验证的独立工作树](03-ticket-worktree.md)

**Status:** ready-for-agent

**GitHub 实施票：** [#9](https://github.com/linxiovo/deepseek-harness-dev-hub/issues/9)

**对应规格：** [S08](../spec.md#s08)

**依赖理由：** 需要 03 提供的实际候选基线与工作树；用目标仓库现有测试入口即可验收，不依赖 CI 连接器或双路审查。

## 验收条件

- [ ] 在小仓库改变公开行为，先在公开接口观察预期失败，再做最小修改并重跑；证据带候选版本、实际运行项、范围依据和结果，能在该树重现。
- [ ] 改一模块的内部行为时开发循环先跑该行为；改变对外契约，合入前范围包含实际使用方，仓库原有必需 CI 不被删去或降为可选。
- [ ] 改公共测试基础设施或无法可靠界定影响时选择全量套件；没有专门入口时补公开验证入口或运行能覆盖的现有套件，均未运行不能出绿色结果。测试选择适用于不同语言的仓库惯例。
