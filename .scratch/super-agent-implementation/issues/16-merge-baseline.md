# 16: 在同一主干队列上合入并核验实际基线

**执行角色：** backend

**What to build:** 两份已通过单票检查的候选投往同一主干时排队合入。票上显示实际使用的基线与结果；中枢安排执行者解决冲突，而不是请人手工合并。

**Blocked by:** [15 完成两次 retro 并重新取得失效证据](15-retro-evidence.md)

**Status:** ready-for-agent

**GitHub 实施票：** [#17](https://github.com/linxiovo/deepseek-harness-dev-hub/issues/17)

**对应规格：** [S12](../spec.md#s12)

**依赖理由：** 15 交付经过复盘与验收、可排队的版本化证据。这里验证合入结果，不负责释放依赖。

## 验收条件

- [ ] 在同一 Git 目标上同时排 A、B；可观察到同时最多一个合入，记录候选、意图、目标基线、实际主干提交和核验结果。不能借另一个 PR 路径绕开合入队列。
- [ ] A 合入后 B 的基线改变，制造代码冲突和文档路由冲突。中枢委派 Worker 修复，重核受影响的审查、验收、测试、文档路由及语义；旧基线通过记录不充当新基线证明。失败时保留真实等待/修复状态。
- [ ] 在合入意图落库后、以及 Git 已合入而回执未记录时中断；恢复时比对实际主干，分别继续或补记结果，不能二次合入。仅关闭 PR 不产生成功合入证据。
