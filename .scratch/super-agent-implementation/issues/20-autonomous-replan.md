# 20: 停滞或需求改变时保留承诺地重排计划

**执行角色：** backend

**What to build:** 中枢遇连续无进展时能在额度内改派、拆并或补技术修复；已授权者改变需求时先看到哪些票和验收会受影响。

**Blocked by:** [14 按生效预设和在途用量限制新工作](14-run-limits.md)

**Status:** ready-for-agent

**GitHub 实施票：** [#21](https://github.com/linxiovo/deepseek-harness-dev-hub/issues/21)

**对应规格：** [S19](../spec.md#s19)、[S22](../spec.md#s22)

**依赖理由：** 14 交付实际的停滞与额度策略、作用域暂停；其上游计划登记已检查引用及环。没有有效授权和额度的重排不可执行。

## 验收条件

- [ ] 让一项技术检查反复失败，中枢依据生效策略改变诊断/改派/拆并路径，技术或跨票冲突不请人修；新计划保留原承诺，更新依赖能查到原因及可工作范围。
- [ ] 尝试以删承诺、降低验收、忽略失败、删除失败检查、扩权或引入无效边/环来解阻，均不生效；当前计划和失败事实仍可见。无可用额度时暂停并如实报告，不继续消耗。
- [ ] 经授权的需求变更先列受影响的票及失效的验收/证据，再据新目标重排并要求相应重验；不清楚所指目标时只问必要问题。来自技术建议或无权限者的信息不能冒充产品授权。
