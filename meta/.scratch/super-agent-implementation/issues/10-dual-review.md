# 10: 在 implement 内并行取得两份独立审查结论

**执行角色：** backend

**What to build:** 从 implement 中同时委派规范审查和规格/票据审查；票的候选详情可分别取回两路身份、依据、版本和阻塞结论，并核验后端接口契约文档完整一致。

**Blocked by:** [07 随候选改动交付 Doc Tree 影响判定](07-doc-impact.md)；[08 在 Worker Session 内按影响完成红绿验证](08-scoped-tdd.md)

**Status:** ready-for-agent

**GitHub 实施票：** [#11](https://github.com/linxiovo/deepseek-harness-dev-hub/issues/11)

**对应规格：** [S07](../spec.md#s07)、[S09](../spec.md#s09)、[S33](../spec.md#s33)

**依赖理由：** 07 交付可审查的文档差异（含接口契约文档）或无影响理由；08 交付可复验的候选改动及选测记录。需要两者来评审同一项真实实现，而非评审空壳。

## 验收条件

- [ ] 让一路审查等待，另一路仍已收到同一基线和候选提交；来自两个独立 code-review 会话，不由实现者写两份总结替代。
- [ ] 规范路逐项核对项目约束及文档语义（含后端 API 契约文档与源码一致性和无更新理由），规格路按规格与票据验收核对行为与测试。引入「链接全对但行为说明或接口入参写错」「改了接口却缺接口文档」或漏交一项验收，相应路报告阻塞。
- [ ] 缺规格、缺一路结论、不同基线/候选或未消除的阻塞均不能得到双审通过；修正后匹配版本的两路非阻塞结论可检视。
