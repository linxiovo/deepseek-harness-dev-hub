# 03: 中枢 Agent（Hub Agent）DAG 调度闭环与上下文防膨胀机制

Type: grilling
Status: resolved
Blocked by: 01, 06

## Answer

### 中枢与程序的职责

- 中枢决定派工、修复策略与计划调整；程序保存真实执行状态，检查重复认领、前置依赖和交付证据。异常恢复策略不固化为单一路径，但中枢不能绕过这些检查。
- 中枢不配备 Bash 或直接修改目标仓库的工具，通过受约束的协调工具查询事实、管理执行会话和传递指令。

### 关票与依赖释放

- 默认流程：implement 内双路审查 → retro 与修复 → 验收检查 → 最终 retro 与必要修复 → 合入验证 → 正式关票并释放后继依赖。
- 后续修改影响已有审查或测试结论时，重新核验受影响部分；不能沿用失效的通过结果。
- 执行会话自报完成不等于交付完成。正式关票必须有验收、审查、相关测试、文档一致性和主干合入结果的支持。

### 执行计划调整

- 中枢可以拆并票据、调整依赖及补充技术修复工作，但不能删除已承诺功能、降低验收标准或通过忽略失败伪造完成。
- 产品意图缺失时请求人类澄清；技术实现与跨票冲突由中枢自主处理。

### 复盘改进范围

- 影响当前票正确性、安全或现行质量标准的问题必须在关票前修复。
- 纯可选优化进入持续演进的独立待办，不自动扩大当前票或当前计划的完成条件。

### 异常恢复与资源边界

- 在预先授权的资源额度内自主诊断、改派或重拆；反复无进展时改变恢复策略，不盲目重复同一操作。
- 额度耗尽而仍不能推进时，暂停受影响工作并报告真实状态，不要求人类修代码，不擅自扩大授权或伪造关票；其他未受限制的票继续推进。
- 运行配置提供默认预设，并允许用户自定义覆盖资源额度、并发、停滞处置策略，以及分角色模型配置（必填后端模型、前端模型，可选轻量检索小模型）；不把这些数值或模型写死在 Skills 中。启动时展示生效配置并沿用入口授权，中枢不得自行提高已授权上限。

### 会话计量接口

- 插件必须提供按 Session 查询上下文信息及累计 token 消耗的接口，并提供按票据、计划或项目汇总总消耗的接口；中枢和面板读取同一份计量事实。
- 上下文占用与累计 token 使用量分开记录。上下文快照包含模型、窗口容量、占用值、采样时间和是否估算；压缩或更换会话不能把已发生的消耗清零。
- 用量至少区分输入与输出；模型提供缓存或其他细分字段时保留来源语义，不把已包含的数值重复相加。模型未提供的数据标记为未知或估算，不用零替代。
- 汇总关联中枢、实现、审查、复盘及重试会话；区分父会话自身消耗和包含子会话的合计，避免重复累计。
- 默认预设和自定义资源策略基于可观测数据执行；缺失计量时明确报告可计量范围，不能声称已严格控制不可观测的额度。宿主字段来源与接入方式见[会话 token 与上下文计量能力](./06-session-metering-capabilities.md)。

### 中枢上下文

- 中枢对外身份持续，底层会话允许按需压缩或换新。
- 目标、约束、票据当前状态和待处理事件独立持久保存；聊天上下文不是唯一事实源。
- 中枢只加载当前决策所需的摘要与引用，必要时读取具体证据，不常驻全量 Worker 对话或仓库内容。
- 会话轮换后依据持久化事实接续工作，不把讨论历史或会话摘要写入仓库文档。

### 自动接续与并发推进

- 入口需求对齐完成后，中枢委派规格生成与拆票会话，在已确认目标内承接原 Skills 的确认职责；不能代替人类编造缺失的产品意图。
- 程序验证依赖关系、原子认领票据并检查并发槽位。中枢从前置条件满足的未认领票中按角色标签（`backend` / `frontend`）与对应配置模型安排执行，代码检索与只读巡检优先路由到已配置的轻量小模型；每张实现票使用独立 Worktree；同一份工作目录同时只允许一个修改者。
- 实现可并行，修改同一主干的合入动作排队执行，并核对实际合入基线上的验收结果。关闭但未交付、取消、失败或仅自报完成，都不能直接释放后继依赖。
- 所有必需票满足交付条件后，当前计划结束，中枢转入持续演进；纯可选优化待办不阻止当前计划完成。

### 持续运行的事实一致性

- 调度动作、会话归属和待处理事件在执行前落入持久化状态；恢复时对照执行结果处理，不仅凭聊天摘要重复派单或重复合入。
- 中枢会话轮换在可交接边界进行，由程序切换当前调度权并保留未处理事件；旧会话不能继续发出有效调度指令。
- Token 汇总与上下文快照都携带采样范围。跨多票的中枢批处理调用记为项目共享开销，不凭空均摊；票据或计划查询区分可归属用量和共享开销，项目总量以去重调用记录为准。
- 严格限额需要的计量缺失时暂停相关新派发并报告；并发在途请求纳入资源检查，不能只在全部完成后才发现共同超限。
