# 03: 为每张票交付可验证的独立工作树

**执行角色：** backend

**What to build:** 接受一张现有票后，从其执行详情可定位真实 Git 工作树、分支、准备基线和唯一有效写入者；失败或重试不把他票目录交给新会话。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**GitHub 实施票：** [#4](https://github.com/linxiovo/deepseek-harness-dev-hub/issues/4)

**对应规格：** [S04](../spec.md#s04)

**开工依据：** 在已有按票 Session、执行目录和 prepare 扩展上补强校验；不依赖多节点调度。

## 验收条件

- [ ] 用临时 Git 仓库接受两票，验证各自的 Session、票归属、分支和基线可查；在一棵工作树修改文件，另一棵树与主干内容不变。
- [ ] 将普通已存在目录、他票工作树或不匹配的基线作为准备结果，启动被拒并可查原因；已有非空内容和他票工作树不受损。
- [ ] 让两个尝试同时申请同一目录，只有一个有效修改者。重试须在旧写权已释放、归属和基线吻合后才可复用；已准备过不等于可直接复用。
