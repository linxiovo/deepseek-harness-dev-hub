# DeepSeek Harness 全自动研发中枢插件：从交棒到持续维护

Type: spec  
Label: ready-for-agent

## Problem Statement

项目负责人能说明想得到什么，却不应为了拿到可用产物而逐票催进度、读代码、审批测试边界或解决 Git 冲突。今天，某个 Worker Session 说「做完了」、某个 PR 关闭、代码已合入、产物已验证、生产已上线，是五件不同的事。负责人需要知道哪件事真的发生了、哪里需要自己行动，以及不受阻的工作是否仍在推进。

## Solution

以 DeepSeek Harness（D-SH）的 Cordis bundle 原型为底座，演进为支持**多项目工作台、首次强制 GitHub 引导、前后端/小模型分工路由及前后端分离拆票**的全自动研发中枢插件。插件入口挂载在 DSH 左侧全局导航（不替换原生「工作区」），首次上手强制完成 GitHub 连接与模型配置后才允许建项目。入口复用微调后的 DSH 原生对话栏配合 `grill-with-docs` 或 `wayfinder` 对齐目标、验收与授权；确认即越过 Human Handoff Boundary。之后由项目对应的 Hub Agent 对人负责，委派规划会话生成规格和「后端与接口契约先行、前端依赖后端契约」的 Plan DAG；每个 Worker Session 按票据角色路由对应模型并在独立 `git worktree` 中交付切片票据。支持本地桌面（随窗口启停）与可选服务器 24h 常驻模式。所有必需票正式交付后验证集成版本；默认交付产物，不默认上线。

## User Stories

以下 **S01–S33 是首版要达到的验收契约，不是原型功能清单**。同一编号下的正例、拒绝路径和可见结果均须满足。

### 交棒、派工与接续

1. <a id="s01"></a>**S01 · 只有中枢对外协调。** 作为负责人，我要知道谁有权对外说话、谁能改仓库。验收：实际 Hub Agent 工具集允许检视状态、证据摘要、调度会话与路由事件，并支持只读查看与检索仓库代码/图片（`read`、`read_image`、`glob`、`grep`、`skill` 及只读评估接口）；调用 Bash/Shell、后台作业或写/改文件工具均被拒绝，不只靠提示词。Worker Session 能在授权工作中编码、测试、向中枢报告，但不能借确认回执或通道工具直接联系用户；结束的执行会话不能再修改仓库。
2. <a id="s02"></a>**S02 · 在 Harness 交棒即出规格。** 作为需求方，我希望不绑定 IM 也能在「与中枢对话」中启动、收提问、回复和查看验收。验收：交棒记录持久保存已确认目标、约束、验收范围与授权；Hub Agent 委派规划会话运行无人值守版 `to-spec`，返回含用户可观察验收、公开测试接口与范围外事项的规格。不向用户再确认技术测试边界；若无法从材料判定一个会改变产品目标的意图，只问缺的那一点，得到答复后接续，不替用户编造答案。
3. <a id="s03"></a>**S03 · 规格自动成为前后端分离的 Plan DAG。** 作为负责人，我不想再发「继续」或手工排依赖。验收：规格产出即委派无人值守版 `to-tickets`；涉及前后端协同的功能必须拆分为**「后端 + 接口契约文档票」与依赖它的「前端页面票」**，各自按独立可演示的功能切片组织并标注 `backend` / `frontend` 执行标签；后端票交付接口文档后，前端票才进入可派发 Frontier。中枢核对拆分、粒度、覆盖与依赖；程序拒绝重复节点、缺失引用、自依赖、环及违反「后端契约前置」或「无接口文档要求」的跨端混杂拆票，非法图不派工。单点维护也登记为一节点计划；一次交棒可生成多票，计划根话题的上下文不等于所有节点都获得执行指令或新授权。
4. <a id="s04"></a>**S04 · 一票一棵真实工作树。** 作为执行者，我需要隔离候选改动。验收：派发后可查票、Worker Session、目标仓库、工作树、分支及准备时基线的对应关系；两个并行写入者不会拿到同一工作目录。重试只接管匹配该票且已释放写权的树；普通目录、他票工作树或错误基线不能因「目录存在」而获准开工。准备失败不污染主干或他票。
5. <a id="s05"></a>**S05 · 只派 Frontier。** 作为 Hub Agent，我要从所有前置已交付的未认领票中选择，并用足授权的空槽。验收：两张无依赖票有两个槽时均可启动；第三张依赖两者则等待。两个调度请求同时认领同一票或争最后一槽，最多产生一个有效派发；先持久化认领、会话归属和待处理动作再执行。重放输入或重启不多占槽、不重复启动；Worker 自报 `ready` 不能改变后继的可派性。
6. <a id="s06"></a>**S06 · 换会话不换身份或重复派工。** 作为负责人，我希望长时间运行仍由同一个中枢接续。验收：上下文压力下允许压缩，或在可交接边界换新底层 Session；新会话用持久化的目标、授权、票态、未决事件和动作结果接手，只载入当前决策的摘要及证据引用。交接中到达的事件不丢，旧会话的迟到调度指令无效；已派发的工作不重派。聊天记录不是恢复凭据，不把会话摘要写进仓库文档。

### 单票质量、合入与计划交付

7. <a id="s07"></a>**S07 · 每票检查 Doc Tree 与接口契约影响。** 作为下一位维护者，我要沿职责路由找到一份当前事实。验收：`doc-tree` 优先沿用目标仓库约定；无约定用根与模块旁的 `DOCS.md`，宿主自动载入的文件只放精简入口。非叶节点只给职责与下级的名称、职责摘要、相对路径；叶子按最小完整职责写实际存在的契约、约束、代码/验证入口与必要依赖，同一事实只写一处。后端票新增或修改对外 API/数据契约时，必须把接口路径、方法、入参出参、错误码与验证入口同步写入对应接口契约叶子，供后继前端票消费。已知叶子直接读，未知沿路由找；遇缺失或矛盾时定点查源码并纠正，不要求全仓扫描。每票在自己的树检查行为、接口、依赖、运行/验证方式及模块增移删；有变化就把文档与代码同交付，结构或路径变动才改相应上级路由；无变化给出供独立审查的短理由。机械查断链、无效入口和不可达节点，独立审查查语义。失效内容替换或删除，不保存讨论、复盘叙事或历史归档。
8. <a id="s08"></a>**S08 · 选测范围随影响改变。** 作为 Worker Session，我要在 `implement` / `tdd` 中用 `test-scope` 找到仓库已有的公开验证入口。验收：行为变更先在该入口得到预期失败，再以最小改动重跑到通过；开发循环先验当前行为，合入前覆盖受影响模块及契约使用方，保留仓库必需 CI。公共基础设施变动或影响不明直接全量回归；无针对性入口时补入口或运行能覆盖的套件。证据列候选版本、实际检查、选择依据和结果，「没跑」不算通过。
9. <a id="s09"></a>**S09 · 两路审查不能互相代签。** 作为负责人，我要知道候选既合项目规范又满足需求。验收：`implement` 内并行启动两个独立 `code-review` 会话，分别对照项目规范（含文档与接口契约语义）和规格/票据验收；两路收到同一基线和候选提交，各自给出结论、阻塞项。后端票变更了接口却缺少或错写接口契约文档时，规范路必须阻断。缺规格、少一路、版本不符或有阻塞项都不能记为通过。
10. <a id="s10"></a>**S10 · 复盘用于修错，不用于扩大本票。** 作为维护者，我希望修复不会留下过期的通过结果。验收：双路审查后依次做 `retro` 与修复、逐项验收检查、最终 `retro` 与必要修复；凡改动使先前审查、文档判定、测试或验收失效，补齐受影响的重验。`delivery-check` 汇集匹配候选/基线的证据，区分「可排队合入」与「已交付」。正确性、安全或现行质量标准问题不修不能过；纯可选优化进独立待办，不阻止本计划，也不把复盘过程写进 Doc Tree。
11. <a id="s11"></a>**S11 · 能追到 GitHub Actions 的实际结果。** 作为中枢，我要消费可核查的摘要而非猜测 PR 状态。验收：首期从 GitHub Actions 取得关联票/计划、候选提交或集成版本、必需检查集合、各项运行状态、证据链接及产物引用。失败、取消、未运行、等待或错误版本都不满足必需检查；同样的结果约定可供其他 CI 接入，不依赖 Jenkins 实例。
12. <a id="s12"></a>**S12 · 同主干合入排队，基线动了要重验。** 作为并行开发者，我希望两张各自通过的票不会拼成坏主干。验收：实现可并行，对同一主干的合入一次只有一个；持久记录目标基线、候选、合入意图和实际结果。前票改变基线、发生代码或文档冲突时，由中枢安排 Worker Session 处理，按真实合入基线重核受影响的验收、审查、测试和文档路由/语义；未获有效证据不当成成功。中断在「合入已发生、回执未记」时，恢复后先对照实际主干，不二次合入。
13. <a id="s13"></a>**S13 · 只有正式交付才能解锁。** 作为后继票的执行者，我要依赖真实可用的前置。验收：程序核验同一交付版本的验收、双路审查、相关测试及必需 CI、文档一致性、必要复盘修复和主干合入验证，再正式关票；`delivery-check` 的文字结论无特权。自报完成、PR 仅关闭、未交付即关、失败、取消、停止或过期证据都不解锁。所有前置正式交付后才把后继暴露给 Frontier；重复回执不再次关票或派工。
14. <a id="s14"></a>**S14 · 交付验证过的集成产物。** 作为需求方，我想拿到可安装软件包、可运行程序或预览环境等适合项目的产物，而不只是合入通知。验收：所有必需票已交付后，在实际集成版本做整套回归；仅同一版本、测试配置与相关环境的可信全量结果可复用，否则重跑。回归失败或缺少可取得的对应产物，计划不报完成；成功给出验证和产物入口。无生产授权停在产物；若上线也是承诺，则此时只报告已合入、待发布验证。纯可选待办不挡计划收尾。
15. <a id="s15"></a>**S15 · 上线是独立的授权和结果。** 作为环境负责人，我只允许把已验证产物发布到入口明确授权的目标环境和范围。验收：仅有凭据、调高额度或获准修复都不能触发生产变更；有发布承诺而缺凭据时等待受控配置。有完整授权和凭据才发布；按目标环境验证同一产物后才把含上线承诺的计划记为完成。发布或上线验证失败如实报「已合入，未上线/未验证」，不得报计划已交付。

### 计量、限额与修复策略

16. <a id="s16"></a>**S16 · 分开查 Session 上下文与累计消耗。** 作为中枢，我要区分「窗口还剩多少」与「已经用掉多少」。验收：按 Session 查询时，上下文快照给出模型、请求与响应合计的窗口容量、占用、采样时间/范围、来源和实测/估算/未知标志；上次输入量和压缩遮蔽量不冒充此刻精确占用。累计用量纳入已报告的消息、中断、失败/重试/取消尝试、压缩摘要调用；同一调用的流、消息和压缩观测只入账一次。非缓存输入、缓存读/写、输出分列；可用的权威总量与已知分项合计分列，不重复加推理或已含的分项。缺用量、仍在途或缺容量时给出覆盖范围，不填零，不声称是供应商最终账单。
17. <a id="s17"></a>**S17 · 同一笔调用在项目中只算一次。** 作为负责人，我要在面板和中枢看到同一份票、计划和项目计量。验收：持久关联 Session、角色、票、计划和业务父子关系，包含中枢、实现、审查、复盘、重试及巡检；Session 自身与含子会话小计分列。fork 来源不等于派工父子，继承前缀不再入账；压缩、轮换或重启重放不丢失或重复累计。跨票中枢调用记项目共享，票/计划查询区分可归属量与共享开销，不平摊；项目总量按唯一调用结算。票详情分列各会话快照与累计，计划/项目视图显示采样时间、范围、来源、质量标记和共享开销。
18. <a id="s18"></a>**S18 · 依生效配置而不是凭感觉用额度。** 作为授权人，我要在启动及设置处看到默认预设、自定义覆盖、生效资源额度、并发与停滞策略。验收：中枢不能自行提高上限，Skills 不写死数值；并发在途请求也纳入准入检查，不能让两个请求同时花同一份余额。耗尽时如实报告并暂停受影响工作；严格限额所需计量缺失时报告可计量范围并暂停相关新派发，不把未知算作宽裕。有独立授权及余量的工作仍可走。
19. <a id="s19"></a>**S19 · 技术失败可改策略，不能改承诺。** 作为负责人，我不想被叫来修测试或解跨票冲突。验收：中枢在既定额度内根据失败证据诊断、改派、拆并票、调依赖或补修复票，反复无进展时改变策略；重排后仍覆盖所有已承诺验收、通过引用与无环校验。删功能、降标准、忽略失败、删失败检查或自行扩权的重排不能生效；真正缺产品意图才请人澄清，额度耗尽则停并报告，不无限重试。
20. <a id="s20"></a>**S20 · 共享规则与自定义 Skills 不能被待审者热换。** 作为维护者，我希望团队/用户自定义 Skills 与规则改进能惠及后续任务而不能让当前任务给自己放行。验收：插件提供自定义 Skills 的加载与启停管理；本票授权范围内可改项目检查、测试、导航，仍须独立审查；跨票共享 Skills、自定义 Skills 或全局规则通过设置或独立维护任务验证并独立审查新版本。运行中的任务及其重验使用启动时绑定的版本；新任务才可绑定已生效版本。删检查、降验收、扩大权限或额度不能成为过关手段。

### 负责人看见什么，以及交付以后

21. <a id="s21"></a>**S21 · 卡一张票不等于卡整个计划。** 作为负责人，我只想收到确需我行动（意图或凭据）、受影响工作因额度暂停、计划交付这三类主动推送。验收：消息说明工作、影响范围、所需动作或结果，同一卡点只提醒一次。三票并行时仅一票缺测试账号，Harness 显示「2 张执行中，1 张待你处理」，只给受控配置入口，不在聊天索取或显示密钥；无关两票继续。补齐后须验证才解阻。逐票进度、技术重试、审查与关票可查而不逐条推送；交付推送指向已验证产物，有发布承诺时另列实际发布及验证结果。
22. <a id="s22"></a>**S22 · 能定向干预而不抹掉已发生的事。** 作为有权限者，我要在对话中查询、按票或全计划暂停/恢复，或明确改变需求。验收：暂停一分支后不再对它新派工、合入或发布，后继仍等，无关票继续；明确全停才停全计划。对在途操作区分「已请求停止」「已停止」「已经发生」，不承诺撤回已发布产物。恢复重查凭据、前置和额度。改需求先列受影响票与失效验收，再按授权的新要求重排；指代不清只问必要范围，未经授权者不能改状态。
23. <a id="s23"></a>**S23 · 飞书只提供另一个入口。** 作为项目成员，我希望有权限者能选项目和目标私聊/群话题，确认绑定一次即可在原处接续 Harness 中的同一个中枢。验收：能按真实身份接收回复，向指定话题发消息并链接回项目；两入口读取同一状态。绑定不给群成员项目权限，不把私聊自动转群，Worker Session 不另拉群。通道不具可信卡能力时只发文本摘要及受权限控制的操作链接，普通文本不能模拟批准。不绑定仍可完成全流程。
24. <a id="s24"></a>**S24 · 授权人可在 IM 卡内批准配置。** 作为授权人，我要在卡上看到项目、对象、当前值、新值和生效影响后直接批准调额或扩大监听范围，不必去网页。验收：插件核验真实操作者、权限作用域、原绑定及配置版本；重复点击只生效一次，未授权、转发、过期、已被取代、文字「同意」或中枢转述均无效。Harness 设置页也能完成确认，同时操作只落一个有效版本，两处读回同一结果；卡片不含密钥，调额不授予上线权。
25. <a id="s25"></a>**S25 · 依赖图先回答「哪里需要我」并分端统计。** 作为负责人，我要从入口打开 Plan DAG。验收：默认聚焦执行中、待人处理及它们的直接依赖，可切换全图；支持按 `backend` / `frontend` 标签筛选并分别统计后端票数、前端票数及完成进度；一票一节点，多前置多条边。节点用文字写票名、执行端标签、当前动作、等待原因，不只靠颜色；只有全计划暂停或确无可推进工作才把等待标在计划层。点击可查验收、工作树、接口文档引用、执行/两路审查状态、验证与产物入口；不把 Doc Tree 混画在图中。
26. <a id="s26"></a>**S26 · 预览的文档有明确版本。** 作为读者，我希望 Doc Tree 独立入口默认读 main（或配置的主干），从票据才看该票候选。验收：两票各改一份文档，主干视图不出现未合入内容；选一票只读其工作树并标明工作树和「未合入」，不拼接其他候选。切回主干或合入后按实际版本展示，并支持在原生对话右侧边栏停靠查看。
27. <a id="s27"></a>**S27 · 交付后按授权监听工作事件。** 作为长线维护者，我希望完成所有必需交付（含约定的上线）后转入 Stage 2 常驻监听。验收：符合项目、来源/群、话题与规则授权的事件可不经点名触发核查或新计划；单点工作走同样的单节点 Plan DAG（跨端需求仍按后端先出契约、前端后置拆票）。重复反馈关联已有票，闲聊不派工；可读消息、入群、引用或转发均不扩权，也不重开已交付计划。
28. <a id="s28"></a>**S28 · 空闲巡检是一份单独的授权。** 作为仓库负责人，我可以不启用巡检。验收：默认关闭，无任务/事件时无扫描，正常事件响应与每票文档影响检查照常；显式给检查对象、频率和资源额度才可定时检查。只授权检查时用只读会话（优先路由给配置的轻量小模型），没发现即结束，有发现只关联或建待办，不改代码/文档、不重开旧计划。另有范围内修复授权才建独立修复计划，照走派工、审查、测试、关票，不据此上线。巡检会话计入项目用量，耗尽只暂停受影响工作。

### 首次上手、多项目入口、模型分工与运行模式

29. <a id="s29"></a>**S29 · 首次使用先过新手引导并强制绑定 GitHub。** 作为首次安装插件的负责人，我希望打开入口就被引导配好必要条件，未连 GitHub 前不误操作建项目。验收：未完成初始化时打开左侧「研发中枢」入口显示 3 步新手引导：① 连接并验证 GitHub（首版仅默认支持 GitHub，连通校验未过时禁用新建项目与派工，并指出缺项）；② 配置分工模型；③ 确认默认预设及运行提醒。GitHub 凭据与身份上下文持久保存并自动注入中枢与所有 Worker 会话上下文，无需人重复提供。
30. <a id="s30"></a>**S30 · 按前端、后端与可选小模型分离配置和派工路由。** 作为负责人，我要让专业前端模型做页面、后端模型做接口与逻辑、可选小模型做轻量检索。验收：初始化与设置页要求配齐后端模型与前端模型，可选填轻量小模型（未配置前后端模型禁止开启项目派工）；派发 `backend` / `frontend` 票时实际 Worker Session 按票据标签使用对应模型；配置了小模型时，代码库检索、Doc Tree 路由定位、只读巡检与摘要等轻量任务优先使用小模型，未配置时回退默认模型。
31. <a id="s31"></a>**S31 · 多项目工作台、原生工作区保护与微调对话入口。** 作为桌面端负责人，我要在一个 DSH 界面里管理多个项目并保留熟悉的对话习惯。验收：左侧全局导航（`sidebar.panellist`）挂载「研发中枢」入口，主面板内提供多项目切换与「+ 新建项目」，各项目独立隔离本地工作区、GitHub 仓库、授权预设、Hub 会话与状态，互不串扰；不替换或破坏 DSH 原生「工作区」标题栏与列表，仅在关联会话行附加状态角标与悬停快捷跳转。发起或推进项目时复用 DSH 原生对话栏并做定向微调：顶部显示当前项目与阶段条及一键展开 DAG 按钮，对话内嵌入交棒确认与受控配置卡片，右侧停靠栏可同步预览 Plan DAG 与 Doc Tree。
32. <a id="s32"></a>**S32 · 本地随窗口启停与可选服务器 24 小时模式。** 作为负责人，我要既能在个人电脑上即开即用，也能在需要时部署 24 小时常驻监听。验收：本地桌面模式下，插件随 DSH 客户端运行并在引导/状态处明确提示「关闭软件或电脑关机/休眠会暂停任务与监听」，重启打开后基于持久化状态安全续跑而不重复派工或重复合入；在服务器无界面模式（headless profile）下可 24 小时持续执行与监听授权事件，桌面端可连接该后台实例读取与操作同一份状态。
33. <a id="s33"></a>**S33 · 本插件与外部项目一律贯彻前后端分离与分端统计。** 作为负责人，我要保证无论开发本插件还是用本插件开发其他项目，前后端票据边界和完成情况都清晰可见。验收：本插件实施票与受托生成的 Plan DAG 均显式区分 `backend` 与 `frontend` 票，后端与接口文档交付前，依赖它的前端票保持等待；前端 Worker 收到已交付后端接口契约文档作为启动上下文；面板与查询接口均输出后端票数、前端票数及各自完成进度。

## Testing Decisions

- **主要边界：从 Harness 插件的项目入口驱动。** 给定已确认的授权、真实的候选版本，从左侧「研发中枢」入口、3 步新手向导、已挂载的会话工具、管理请求或来源事件进入，观察对话、计划/票查询、执行会话收到的模型与工作、实际工作树和交付产物。不以内部表形状、提示词里有某句话或 Worker 的自评分作为通过条件。沿用原型的 Runtime 宿主夹具与并发事件测试、同源管理 HTTP 请求测试；用受控的同时请求、中断及重启检验 S01–S06、S12–S13、S18–S24、S29–S33，而非靠等待时间猜状态。
- **交付要看仓库和服务端结果。** 用临时 Git 仓库、独立工作树和带使用方的小模块演示前后端分离拆票（后端先交接口文档再解锁前端）、红绿循环、双审、文档移动、基线变化及复盘后重验（S03–S04、S07–S13、S20、S26、S33）。服务边界可重放 GitHub Actions 的失败、取消与陈旧回执；首期打通以测试仓库的实际 Actions 运行、对应集成提交与可取得产物为证（S11–S15）。在受控目标环境验证发布条件，不需要为验收变更实际生产环境。
- **只在外部不可控处给定输入。** 按固定宿主事件提供含缺字段/重放/fork 的用量样本，比较 Hub Agent 查询与面板读数，不用模拟值宣称已测得真实账单（S16–S18）。用有/无权限身份和重复、过期回调检查飞书；从 Harness 入口实际打开引导向导、多项目工作台、微调原生对话、依赖图（含前后端分端统计）、票据、计量与文档，检查局部阻塞、版本标示与本地重启接续。用授权事件和可控时钟分别触发监听与巡检，观察有无派工、待办、仓库写入和消耗（S21–S32）。
- **交棒自检。** 测试边界由规划会话依据上述公开入口确定；拆票按前后端分离与接口契约前置原则拆出后端模型票与前端模型票，以一个新鲜上下文可完成、能单独演示正例和拒绝路径为准。技术取舍由中枢负责，不新增人工测试确认、拆票审批或逐票验收卡点。

## Out of Scope

不从零自研 LLM Runtime、工具沙箱或进程守护；不替换或魔改 DSH 原生「工作区」组件；不做人类逐票代码审批或手工解 Git 冲突的流程。首版不接入 GitLab/Bitbucket 或个人微信/企业微信连接器，不部署或联调具体 Jenkins 实例。无授权的生产变更、默认全仓巡检、仓库历史叙事归档均不属于交付。核心工作流、Doc Tree 和测试分层不限定目标项目的编程语言。
