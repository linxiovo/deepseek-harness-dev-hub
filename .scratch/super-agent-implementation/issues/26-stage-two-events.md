# 26: 交付后仅按已授权事件发起维护计划

**执行角色：** backend

**What to build:** 计划兑现全部承诺后，Hub Agent 留在同一项目监听已授权工作事件。匹配规则的维护请求不用再点名，非工作对话不会启动 Worker。

**Blocked by:** [19 只在明确授权的环境发布并验证产物](19-authorized-release.md)；[23 在授权的飞书话题接续同一项目对话](23-feishu-binding.md)

**Status:** ready-for-agent

**GitHub 实施票：** [#27](https://github.com/linxiovo/deepseek-harness-dev-hub/issues/27)

**对应规格：** [S27](../spec.md#s27)

**依赖理由：** 19 能区分产物交付、已合入但未完成上线和真正完成；23 提供明确的话题绑定/身份边界，可演示 Harness、GitHub 或已绑定话题的事件，而非把能读消息视为可接单。

## 验收条件

- [ ] 分别完成「仅产物」计划和「承诺上线」计划：在各自最后一个必需交付条件满足后才进入 Stage 2；待验证上线不报收尾。没有新事件且巡检未启用，不派发扫描工作。
- [ ] 在已授权项目/来源、群或话题和匹配规则内送入未点名的工作反馈，可核查或开新的单节点 Plan DAG；重复反馈只关联已有票。未绑 IM 也能处理已授权 Harness/GitHub 入口。
- [ ] 向同一项目送入闲聊、未授权话题、转发、引用或仅入群事件，不新派工、不扩大监听，也不重开已交付的计划。维护票沿用同样的工作树和交付约束。
