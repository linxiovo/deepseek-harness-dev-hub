# 02: AI 文档树协议

Type: grilling
Status: resolved
Blocked by: None

## Answer

### 内容边界

- 文档只保留当前有效的事实、约束与结论，不保存历史沿革、讨论过程、废弃方案或历史复盘叙事；失效内容原地替换或删除，不另建历史文档归档。
- 本规则同样适用于本项目的规划地图、决策票、领域词表及架构文档。规划文档描述当前有效设计，不把待实现能力写成已经实现的事实。
- 复盘只将仍有效的改进落实为当前规则、检查或导航信息，不把讨论过程抄入文档。

### 组织与节点格式

- 复用目标仓库已有的文档命名和导航约定，不另建重复体系。没有约定时，默认以根目录及模块旁的 `DOCS.md` 承载路由或模块说明；宿主自动加载的引导文件只保留精简入口。
- 根节点与中间节点负责职责概述和下级路由，不复制下级文档正文。每个下级入口包含模块名称、职责摘要与相对路径。
- 叶子按可独立理解的职责组织，由 AI 根据任务相关性与职责完整性决定拆分，不按每个函数或文件机械建页。
- 叶子按需包含：职责、行为契约与约束、相关代码入口、验证入口及必要依赖。只写有实际信息的字段，不复述源码或填充空模板。
- 每项事实只有一个权威文档位置；跨模块依赖通过链接表达，不复制同一份说明。

### 阅读与查证

- 已知模块入口时直接读取相关叶子；未知入口时沿文档路由定位，不强制每次从根重新遍历。
- 文档缺失、失效或与源码矛盾时，允许有明确目标的小范围源码搜索和查证，并修正文档；不以导航规则阻止取证。
- 约束无目的的大范围读取，不要求把整棵文档树或全仓源码装入上下文。

### 更新、审查与合入

- 每张实现票必须检查代码变更对文档的影响，包括行为、接口、依赖、运行及验证方式，以及模块新增、移动或删除。
- 有事实变化时更新对应文档和受影响的路由，与代码作为同一交付单元合入；没有影响时记录简短的当前判定理由，由独立审查核对，不强迫无意义地修改 Markdown。
- 机械检查负责可确定的结构问题，例如失效链接、无效入口和不可达节点；语义是否与代码一致由审查核对，不能把结构检查通过当作内容正确的证明。
- 文档问题由执行会话修复后再满足关票条件，不增加人工审批节点。
- 各执行会话只维护自己 Worktree 内的代码和文档；仅在模块结构或路径变化时修改受影响的上级路由。合入时处理文档冲突，并核对合入结果的路由和内容一致性。

### 预览

- 默认读取 main 文档；目标仓库主干名称不同时使用其配置的主干分支。
- 未合入文档只存在于对应执行会话的独立 Worktree，不汇总成一棵共享的候选文档树。
- 查看某张票的候选文档时明确其 Worktree 和未合入状态，不与主干或其他票据的文档混合。
