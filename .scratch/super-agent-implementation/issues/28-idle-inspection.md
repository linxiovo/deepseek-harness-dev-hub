# 28: 在显式授权的空闲巡检中只读生成待办

**执行角色：** backend

**What to build:** 显式启用空闲巡检后，让只读执行会话（配置轻量小模型时优先路由该模型）按授权检查指定对象并产生可追踪发现；关闭时没有后台扫库。

**Blocked by:** [14 按生效预设和在途用量限制新工作](14-run-limits.md)；[26 交付后仅按已授权事件发起维护计划](26-stage-two-events.md)

**Status:** ready-for-agent

**GitHub 实施票：** [#29](https://github.com/linxiovo/deepseek-harness-dev-hub/issues/29)

**对应规格：** [S28](../spec.md#s28)、[S30](../spec.md#s30)

**依赖理由：** 26 提供可区分「空闲」和「有授权工作事件」的维护状态；14 提供真实的巡检额度检查与局部暂停。

## 验收条件

- [ ] 推进可控时钟：默认或缺对象、频率、资源额度之一均不启动巡检；关掉巡检后照常处理授权事件，在正常实现票中仍必须给出文档影响判定并接受审查。
- [ ] 指定检查模块、频率、额度后，到期只读检查该范围（已配小模型时记录使用该模型，未配回退默认模型）；越范围读取或尝试改代码/文档被拒。没有发现就结束，有发现只建独立待办或关联已有待办，重复发现不重复派活。
- [ ] 用实际仓库内容和计划状态确认没有改主干、没有重开已交付计划；巡检 Session 的用量出现在项目归属中，巡检额度耗尽只暂停该范围，无关票继续。
