# 29: 把另获授权的巡检发现交给独立修复计划

**执行角色：** backend

**What to build:** 有单独修复授权时，将巡检发现转成新的修复计划；只读巡检不借机变成能改仓库或发布的会话。

**Blocked by:** [28 在显式授权的空闲巡检中只读生成待办](28-idle-inspection.md)

**Status:** ready-for-agent

**GitHub 实施票：** [#30](https://github.com/linxiovo/deepseek-harness-dev-hub/issues/30)

**对应规格：** [S28](../spec.md#s28)

**依赖理由：** 28 提供有来源、范围与待办身份的巡检发现；已有计划/执行/验证通路由其上游复用，不另造巡检专属交付流程。

## 验收条件

- [ ] 同一发现先只有检查授权，保持待办；加上明确且匹配对象的修复授权才发起独立 Plan DAG。范围外发现不派修复，重放已受理的发现不创建第二个修复计划。
- [ ] 新计划有独立票和工作树，经过双路 code-review、两次 retro 与必要修复、逐项验收、测试、文档核对和合入验证再正式关票；缺任一必需证据均不得旁路。原只读会话与已交付计划未被改写。
- [ ] 只获修复授权不触发生产变更；查询可区分巡检与修复各自的授权、Session 与项目累计消耗。
