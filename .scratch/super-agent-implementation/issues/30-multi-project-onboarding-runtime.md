# 30: 后端 · 支持多项目隔离、强制 GitHub 引导状态与双运行模式

**执行角色：** backend

**What to build:** 在插件后端建立多项目隔离存储与管理机制（每个项目绑定独立本地工作区、GitHub 仓库、授权预设、Hub 会话与状态）；实现强制先连通 GitHub 的全局初始化闸门及全局 GitHub 上下文注入；同时支持本地桌面（随窗口暂存恢复）与可选服务器 24 小时常驻运行模式，并交付接口文档。

**Blocked by:** [02 在 Harness 交棒并自动取得规格](02-harness-handoff-spec.md)；[03 为每张票交付可验证的独立工作树](03-ticket-worktree.md)

**Status:** ready-for-agent

**GitHub 实施票：** [#31](https://github.com/linxiovo/deepseek-harness-dev-hub/issues/31)

**对应规格：** [S29](../spec.md#s29)、[S31](../spec.md#s31)、[S32](../spec.md#s32)

**依赖理由：** 02 提供交棒后的项目身份与规格起点，03 提供隔离的仓库与工作树执行底座；需要在此基础上从单项目单例演进为多项目状态与双运行生命周期。

## 验收条件

- [ ] 初始化状态机首版默认只支持 GitHub：在未完成 GitHub 凭据连通验证前，创建项目与发起流程接口返回明确前置未就绪错误；连通校验通过后，GitHub 凭据与账号身份持久保存并自动注入后续中枢及 Worker 上下文（不泄漏明文密钥）。
- [ ] 在同一插件实例下新建并切换两个项目（各自绑定不同本地工作区、GitHub 仓库与持久化状态）：两项目的交棒记录、Plan DAG、Hub Session、工作树与监听状态完全隔离，不互串事件或工作目录。
- [ ] 验证两种运行模式：本地桌面模式下关闭并重启进程，暴露明确运行模式状态（暂停原因、可恢复工作）并安全断点接续、不重派不重合并；服务器 headless 模式下可持续轮询与监听授权事件，供客户端连接读取同一份状态。
- [ ] 同步交付多项目、引导初始化校验及运行模式接口契约文档到仓库 Doc Tree 对应叶子。
