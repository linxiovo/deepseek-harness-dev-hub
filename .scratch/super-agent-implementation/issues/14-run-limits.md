# 14: 按生效预设和在途用量限制新工作

**执行角色：** backend

**What to build:** 实现默认预设、自定义覆盖、并发在途用量准入控制及限额状态后端接口与接口文档（前端设置页面由 [35 前端设置与用量仪表盘](35-frontend-settings-meter.md) 承接）。

**Blocked by:** [11 在票、计划与项目中查看同一份去重用量](11-plan-meter.md)；[13 缺凭据时只暂停受影响的票并提醒一次](13-scoped-attention.md)

**Status:** ready-for-agent

**GitHub 实施票：** [#15](https://github.com/linxiovo/deepseek-harness-dev-hub/issues/15)

**对应规格：** [S18](../spec.md#s18)、[S21](../spec.md#s21)

**依赖理由：** 11 给出带覆盖范围的归属用量，13 给出定向暂停及只提醒一次的通路；没有二者不能演示并发票各自触限后的实际结果。

## 验收条件

- [ ] 启动项目时对照默认预设和自定义的资源上限、并发及停滞策略，后端查询接口与调度查询都返回一致的最终生效值（附接口契约文档）；Skills 不内置这些数值，中枢尝试自行抬高授权上限无效。
- [ ] 余额只够一个请求时让两个请求同时入场；算上已在途请求后只允许安全的一项，不能等两项都返回才认超限。完成后按实际可观测结果结算，保留缺失/在途区分。
- [ ] 额度已耗尽则暂停受影响工作并按影响范围报告一次；严格上限依赖的 usage 缺失时显示可计量范围，暂停相关新派发。另一份独立授权/余量充足的票仍能执行，不伪造关票，也不自动提高上限。
