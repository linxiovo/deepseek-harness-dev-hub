# 11: 在票、计划与项目中查看同一份去重用量

**执行角色：** backend

**What to build:** 提供票、计划与项目级去重用量统计的后端汇总引擎、持久化投影、中枢工具及带完整接口文档的 HTTP 查询接口（面板前端展示由 [35 前端设置与用量仪表盘](35-frontend-settings-meter.md) 承接）。

**Blocked by:** [04 查询单个 Session 的上下文与累计用量](04-session-meter.md)；[09 按 Frontier 与空槽原子派工](09-frontier-claims.md)

**Status:** ready-for-agent

**GitHub 实施票：** [#12](https://github.com/linxiovo/deepseek-harness-dev-hub/issues/12)

**对应规格：** [S17](../spec.md#s17)

**依赖理由：** 04 提供幂等调用记录/上下文快照，09 提供已派工且关联计划的票与 Session 归属。共享开销必须在真实多票场景中能区分。

## 验收条件

- [ ] 将实现、审查、复盘、重试会话按实际委派绑定到票、计划、角色及业务父子；Hub Agent 跨两票的一次调用只作项目共享开销。在票/计划查询中能区分两者，不均摊。后续只读巡检也能登记角色，不要求其假扮实现票。
- [ ] 构造父会话自耗 10、业务子会话 6、跨票中枢调用 5（均有权威总数），查到自身 10、含子 16、项目 21；子会话带 fork 继承前缀、重启重放或轮换后仍不多加一次，也不凭 fork 来源推断业务父子关系。
- [ ] 后端 HTTP 查询接口（附接口契约文档）与中枢工具返回同一采样：模型/窗口快照、累计输入输出、分项/权威总量、采样时间、来源和估算/未知范围一致；取消且无 usage 和共享用量都不被塞成单票实测零。
