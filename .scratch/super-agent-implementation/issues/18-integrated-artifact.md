# 18: 在集成版本全量验证并交付产物

**执行角色：** backend

**What to build:** 当所有必需票已交付，负责人收到指向集成版本和可取得产物的通知；默认不触及生产环境。

**Blocked by:** [13 缺凭据时只暂停受影响的票并提醒一次](13-scoped-attention.md)；[17 凭真实交付证据关票并释放后继](17-close-unlock.md)

**Status:** ready-for-agent

**GitHub 实施票：** [#19](https://github.com/linxiovo/deepseek-harness-dev-hub/issues/19)

**对应规格：** [S14](../spec.md#s14)、[S21](../spec.md#s21)

**依赖理由：** 17 给出可信的必需票交付集合；13 提供只针对计划交付的对人通知通路。单票通过不等于计划整体已验证。

## 验收条件

- [ ] 最后一张必需票未交付时不发完成通知；全部交付后，在实际集成提交做整套回归。已有可信全量结果仅在集成版本、测试配置、相关环境相同时可引用；换基线/配置/环境则重跑，不要求每个 Worker 重跑同一套。
- [ ] 集成行为失败、只做局部测试、产物缺失或指向另一版本时计划不报交付。成功时从 Harness 打开实际可取得、适合目标项目的包/程序/预览，并查到对应版本与验证结果。
- [ ] 无上线承诺停在已验证产物，成功只发一次计划交付通知，纯可选待办不挡收尾；若入口承诺上线则只显示「已合入，待发布验证」，尚未发送最终完成消息。
