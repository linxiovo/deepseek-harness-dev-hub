# 27: 通过可信 IM 卡或设置页批准配置变更

**执行角色：** backend

**What to build:** 在飞书可信确认卡内或通过受版控的配置确认 API，授权人可以明确批准一项额度或监听范围变更；两路并发确认只落一份生效结果（设置页前端确认表单由 [35 前端设置与用量仪表盘](35-frontend-settings-meter.md) 承接）。

**Blocked by:** [14 按生效预设和在途用量限制新工作](14-run-limits.md)；[26 交付后仅按已授权事件发起维护计划](26-stage-two-events.md)

**Status:** ready-for-agent

**GitHub 实施票：** [#28](https://github.com/linxiovo/deepseek-harness-dev-hub/issues/28)

**对应规格：** [S24](../spec.md#s24)

**依赖理由：** 14 提供实际生效额度，26 提供实际生效监听范围及话题身份。需要验证的是操作后的授权效果与并发版本校验接口，而非一张只显示按钮的卡。

## 验收条件

- [ ] 分别请求调高额度与扩展监听范围。飞书卡面写清项目、对象、当前值、新值及影响，无密钥；真实授权人在原话题卡内可直接批准，并暴露供前端调用的配置确认 API 与接口文档。
- [ ] 同一卡双击、设置 API 与卡同时提交，只有有效项目/对象/版本的一次决定生效；转发、过期、已被取代的卡、无权限身份、普通文本「同意」和中枢转述均不生效。
- [ ] 在飞书与确认 API 重新查询获得相同生效值，下一次受影响派发/监听按新规则执行；受控凭据不在卡片或接口返回中明文回显密钥，调额不会新增上线权。
